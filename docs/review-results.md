# نتيجة المراجعة والإصلاح

آخر مراجعة: [مراجعة 25 أكتوبر 2026](review-2026-10-25.md). النتائج أدناه سجل للمراجعات السابقة؛ راجع الملف الأحدث لنتائج التحقق الحالية وحدودها.

تحديث backend والتطبيق بتاريخ 12 أكتوبر 2026: أُضيفت جلسات PostgreSQL وتسجيل الدخول بالبريد وكلمة المرور، صلاحيات المزارع، إدارة المستخدمين والكتالوج، إعدادات المحاكي، سجل التدقيق، أوامر ري قابلة للإلغاء، ووكيل داخلي لإدارة الخدمات وخطوط Airflow. تفاصيل التشغيل وإنشاء أول مسؤول في [backend-application.md](backend-application.md)، وعقود الإدارة في [API_CONTROL.md](API_CONTROL.md).

نجح 193 اختبار Python للوحدات وsmoke، وفحص Compose لكل profiles وfatal lint. نجح تشغيل API كعملية محلية وفحص liveness ورفض الطلبات غير المسجلة والمقاييس وOpenAPI. راجعت subagents التطبيق بصورة مستقلة وكشفت أخطاء refresh/logout وعزل الحسابات وتعديل IDs؛ جرى إصلاحها مع اختبارات regression. نتائج Flutter: 43 اختبارًا ناجحًا وفحص analyze بلا مشاكل؛ لا يزال تشغيل النظام المتكامل بالحاويات وترحيل قاعدة البيانات الحية معلقًا على توفر Docker.

تمت مراجعة مسار المحاكي وKafka وطبقات البيانات وML وWeather API وClickHouse وGrafana وPrometheus وFlutter للويب والتطبيق. شارك ثلاثة subagents في مراجعة الواجهات، ML/الطقس، والمراقبة، مع دمج التعديلات ومراجعتها في المشروع نفسه.

## التحقق المنفذ

- Python: 244 اختبارًا unit/smoke ناجحًا، تشمل API authentication/farm isolation، الإدارة وأوامر الري وaudit، إعدادات المحاكي، القيم غير الصالحة، فشل snapshot/recovery، ترتيب النشر، migration، Weather، والتدريب الفعلي لـRandom Forest والتقييم الزمني.
- Flutter: 51 اختبارًا ناجحًا، تشمل Dio contract، nullable metadata، refresh/logout والتزامن، عزل الحسابات، نماذج الإدارة، RTL، capability controls، عرض الهاتف والويب، وأخطاء/إعادة المحاولة. flutter analyze بلا مشاكل. أضيفت اختبارات لتباين AA في الوضعين، تكبير النص 2×، إظهار كلمة المرور، بيانات الرسم غير الصالحة، وتعطيل جهاز الري المختار أثناء refresh.
- بناء JavaScript للويب ناجح، وAPI_BASE_URL مضبوط إلى localhost:8000 للبناء المحلي. WebAssembly غير متحقق التوافق بسبب مكتبة التخزين الحالية؛ بناء الويب العادي يعمل.
- فُتحت نسخة الويب في المتصفح فعليًا. كشف الفحص اعتماد بدء العرض على CDN خارجي؛ أُضيف bootstrap يستخدم CanvasKit المحلي، مع حالة تحميل وخطأ، وتحقّق ظهور شاشة الدخول دون أخطاء console. عُدّل تباين عنوان الدخول في الوضع الداكن. المعاينة المحلية تعمل على localhost:8080؛ لا يعني ظهور الواجهة أن قواعد البيانات متصلة.
- Python compilation وfatal lint وتهيئة Docker Compose لجميع profiles ناجحة.
- أداة Prometheus الرسمية `promtool 3.15.0`: التحقق من القواعد التسع ناجح، واختبارات سيناريوهات التنبيه ناجحة؛ صياغة 23 استعلام PromQL في اللوحات ناجحة بعد استبدال متغيرات Grafana بقيم ممثلة. هذا تحقق صياغة وسيناريوهات، وليس تحقق وجود المقاييس في خدمات حية.

## تحسينات الجولة الأخيرة

- هوية واجهات زراعية بألوان دلالية موحدة عبر الصفحات والوضعين الفاتح والداكن، مساحات لمس أكبر، تخطيط يتكيف مع RTL وتكبير النص، رسم رطوبة مؤرخ قابل للقراءة، ونموذج دخول يدعم autofill وإظهار كلمة المرور. القرارات في `App/docs/design-system.md`.
- شاشة أوامر الري تستعلم عن صلاحية المزرعة عبر `/farms/{id}/access` مستقلة عن ClickHouse، وتتجاهل refresh المتأخر وتمسح الجهاز المختار إذا تعطل/حُذف.
- التنبيهات تُراجع اسم المنطقة والمحصول الحالي في PostgreSQL والحداثة قبل العرض والتأكيد؛ تنبؤات ML تتطلب تطابق المحصول وحدود الرطوبة الحالية. الأدلة القديمة بدون metadata تُخفى حتى إعادة تشغيل ML.
- Weather Silver يتحقق من schema_version الأصلي وتوقيت الرصد نسبةً إلى توقيت الجلب؛ كل استجابة مزرعة لها fetched_at مستقل. المحاكي يلتزم بمجال حرارة العقد، وpoison JSON لا يُسقط محلل القبول.
- ML يرفض الملاحظات غير العددية/غير المحدودة والتواريخ الناقصة والاحتمالات خارج المجال، ويختار آخر Gold snapshot عند تساوي وقت الأحداث.
- Grafana يصلح قراءة Kafka offsets كـgauge، الوحدات وتسميات القيم، فلاتر الخدمات والمسارات والمواضيع وحداثة البيانات؛ لا يُظهر غياب القياسات كأنه صفر. Grafana وPrometheus محليان على loopback، وواجهة حذف بيانات Prometheus الإدارية أُزيلت.

Python المحلي 3.14 وsklearn1.9 لا يمثلان تمامًا runtime Spark/ML المعرّف بالحاويات. الاختبارات لا تدّعي مطابقة بيئة الحاويات، ولا تثبت دقة تنبؤ مستقبلية أو صحة تشغيل مضخة.

## ما لم يُطبّق حيًا

حاولنا تشغيل Docker Desktop في الخلفية وعبر CLI، لكن Docker API بقي غير متاح على `dockerDesktopLinuxEngine`. لم يمكن تنفيذ Spark/JDBC، الترحيل، استعلامات Grafana الحية أو إيقاف حاويات موجودة فعليًا. إعداد profiles يجعل الأدوات اختيارية في التشغيل التالي، لكنه لا يوقف حاوية قديمة تلقائيًا.

لم تُحذف volumes أو ملفات Parquet القديمة، ولم تُغيّر staged CI changes التي كانت موجودة قبل العمل. المسارات الجديدة لا تستهلك البيانات القديمة المرفوضة. cleanup/backfill والتشغيل الحي يتبعان خطوات upgrade؛ تسجيل الدخول الجديد يحتاج تطبيق schema وإنشاء أول مسؤول بالأمر الصريح الموثق. API_TOKEN اختياري للقراءة فقط. الموقع بُني محليًا ولم يُنشر على نطاق عام؛ Android/iOS builds لم تنفذ.

توقع الطقس المستقبلي، أحداث الصمامات وعداد الماء، إشعارات Alertmanager، CPU/RAM لكل container، telemetry المقبول/المرفوض لكل job وML drift تحتاج مصادر/توصيلات إضافية. أوامر الري تُحفظ queued؛ تنفيذ المضخة يتطلب executor متصلًا بالجهاز. لم تُعرض هذه البيانات على أنها متاحة في اللوحات الحالية.
